06 · Research agent architecture

How the research was automated, and where a human stepped in

A rule-based Python crawler collects evidence, the Composio SDK adds catalog data and tools, and Groq does the reasoning. Each stage writes a checkpoint, and every claim keeps a link to the page it came from. The crawler is deterministic, not an autonomous agent; only stage 4 reasons.

STAGE 1

Orchestrator

Loads apps.json (100 apps plus candidate official doc URLs), runs batches of 20 with 8 parallel workers, and saves results and progress after every batch.

STAGE 2

Fetch & discover

Cached HTTP fetch with retries and a 1 s per-host delay. JS-only or blocked pages go through a rendering fallback. Follows up to 6 auth / getting-started links per app and probes /llms.txt.

STAGE 3

Signal extraction

Deterministic regex extractors for auth, API type, access gates and MCP mentions. Each hit stores its source URL and a snippet. Also queries the official MCP Registry API.

STAGE 4 · GROQ LLM

Adjudication with tools

STAGE 4b · COMPOSIO SDK

Catalog cross-check

The official composio SDK (v0.34) pulls Composio's toolkit catalog once. For each app it records toolkit existence, tool count and auth schemes, then compares them with the crawler's findings. This is secondary evidence; official docs stay primary.

STAGE 5 · VERIFY

Validate & score

Checks every cited URL against the fetch cache, logs each agent→final correction, and scores every stage against a ground-truth sample of 30 apps built separately from the official pages (LLM-assisted, blind to Groq).

Pipeline run (actual numbers)

    Where a human / LLM was needed

    • Seed discovery. Paygent Connect, fanbasis, iPayX, Waterfall.io, higgsfield, Fathom, Grain, systeme.io and PitchBook had no reliable doc URL in the brief, so they were located by manual web search. For 4 of them no official API docs were found at all, and the dataset records that.
    • Semantics regex can't capture. A "Contact sales" button on a marketing page is not a partner gate, and an "API key" mentioned in an SDK snippet is not necessarily the app's auth model. That's why the Groq stage exists.
    • Ground truth. 30 sampled apps were re-checked against the official pages and vendor MCP repos, blind to Groq's answers, with notes and URLs in verification/ground_truth.json. Fields the evidence didn't settle were left unscored. The ground truth was prepared with LLM assistance and has not yet been re-checked by a person.
    • Credentials. The candidate created the Composio and Groq keys and entered them locally. The agent never saw them. No external app account was connected.
    • Composio account permissions. The first key was read-only for sessions (HTTP 403), so the user created a key with session write access. No app account (e.g. GitHub) was connected, so only a Composio meta tool was executed.
    • Wrong-product matches. 3 catalog matches were rejected on review (Salesforce Commerce Cloud → Sales Cloud toolkit, Mermaid CLI → Mermaid Chart, YouTube Transcript → a different transcript vendor).

    Groq ↔ Composio tool-calling test (real calls)

    How the two SDKs connect

    1. Python fetches Composio's session tool schemas (OpenAI function format).
    2. Conversion: keep a read-only allowlist, trim descriptions, drop session_id. Unit-tested.
    3. Groq (tools=…) decides whether to call a tool. Python executes it (session.execute or the Composio SDK) and returns a role: "tool" message.
    4. A second Groq call with strict JSON Schema produces the final record. Groq doesn't allow tools and structured output in the same request.

      09 · Technical reproducibility

      Run it yourself

      Commands

      git clone <this-repo> && cd composio-app-research
python -m venv .venv && .venv\Scripts\pip install -r requirements.txt
copy .env.example .env   # add COMPOSIO_API_KEY and GROQ_API_KEY
python data/build_apps.py                    # 100-app input
python -m agent.orchestrator --pass 1        # naive crawler baseline
python -m agent.orchestrator --pass 2        # deep crawler loop
python -m agent.composio_client              # Composio connectivity test
python -m agent.orchestrator --composio      # Composio catalog cross-check
python -m agent.groq_client                  # Groq connectivity test
python -m tests.test_groq_composio           # Groq to Composio tool-call round trip
python -m agent.llm_adjudicator              # Groq adjudication, resumable
python verification/build_ground_truth.py    # 30-app ground truth
python -m agent.evidence_validator           # validate + score every stage
python -m agent.pattern_analyzer             # stats -> dashboard/data.js
python -m http.server -d dashboard 8000      # open http://localhost:8000

      Python 3.11+. The crawler uses only the standard library and needs no keys. The Composio and Groq stages need the official SDKs (composio==0.34.0, groq==1.7.0) and their API keys in .env, which is gitignored. Source repo: see the README (no public URL has been published yet).
